## 持续运行与自动恢复

希望异地登录后按时间自动接管时，在 **登录设置** 开启自动重连并配置等待时间。想自行安排上号时间时，可点 **暂停托管** 断开游戏连接，退出游戏后再 **恢复托管** 并开始挂机。手动生产、收成品或改种后，工具接管时会自动同步当前工厂、农田和库存，再按当前状态规划。轮数设为 `0` 并开始挂机后，可以关闭全部网页；任务由 Node 后台进程执行。现代 Windows CMD/Windows Terminal 的顶部固定显示控制台地址和运行提示，日志在下方滚动，调整窗口大小会重新排版。请保持启动窗口打开、电脑唤醒；关闭启动窗口或按 `Ctrl+C` 会结束进程。网络恢复后会自动续跑，重新打开网页可查看后台状态与最近 400 条日志。

## 资源自动更新

控制台和 CLI 持续挂机默认在启动时检查资源，之后每 **30 分钟**检查一次游戏远程版本清单；版本变化才下载配置表和世界地图。资源验证完整后一起启用，正在执行的任务保留原配置和地图快照，下一轮自动使用新版本。失败时保留已有资源并在下个检查周期重试，关闭程序会停止定时器；不需要保持网页或微信游戏打开。

可运行 `npm run sync-resources` 立即更新。运行日志会记录检查间隔、更新或失败结果，`GET /api/resources` 可查询发布版本、最近检查及下次检查时间。默认跟随客户端 `1.14.5` 的发布清单，不代表自动发现未来客户端大版本；协议代码和 UI 图片不在定时下载范围内，`npm run sync-art -- --fetch` 可按当前发布清单补充图片。

检查间隔可通过环境变量设为 1–1440 分钟，例如在 PowerShell 中改为每小时检查：

```powershell
$env:CW_RESOURCE_UPDATE_MINUTES='60'
npm start
```

`CW_RESOURCE_AUTO_UPDATE=0` 关闭自动检查，仍可使用已下载的资源；`CW_RESOURCE_APP_VERSION` 可指定已确认兼容的客户端版本。`CW_CONFIG_PACK` 显式指定配置文件时保留其优先级，并停用远程更新，避免覆盖手动选择。已验证的资源版本保存在 `work/cdn/resources/`；首次下载失败且没有远程副本时，继续从同步副本与微信缓存中按修改时间读取配置。`npm run sync-config` 仍可备份本地配置来源。

城战预览若仍提示缺少 `N_CityCfg`、`N_AttackCityConsumeCfg` 或某联盟主城，请先执行 `npm run sync-resources`；使用微信缓存时，先进入对应地图，再运行 `npm run sync-config` 并重启控制台。仍有异常时请保留提示中的场景、联盟编号和表名，不能用其他场景的主城或费用代替。

## 启动参数

设置 `CW_PORT` 可指定控制台端口，设置 `CW_NO_BROWSER=1` 可关闭启动时自动打开浏览器。PowerShell 示例将端口设为 `17324` 并启动控制台。

```powershell
$env:CW_PORT='17324'
$env:CW_NO_BROWSER='1'
npm start
```

`node tools/start-console.mjs` 和 `.\start-console.cmd` 使用同一个 Node 启动入口，默认端口 `17323`，输出地址与实时日志。追加 `url` 可只输出地址并保持窗口，追加 `status` 可检查抓包证书和上次采集恢复记录。

控制台只监听 `127.0.0.1`，没有登录校验。手机访问需要自行搭建带鉴权的隧道，不要直接暴露到公网。

## 添加账号与抓包

添加账号时，工具会临时安装当前用户测试 CA、启用系统代理并监听登录请求，采集结束后自动还原代理并移除本次安装的证书。CA 文件和代理备份保存在项目的 `certificates/`，停止抓包并成功移除证书后会删除本次生成的文件；明确选择保留 CA 时保留。

- 抓包期间可能把正在玩的游戏顶下线，采集完成后建议重新登录。
- 未连接的账号也可在礼包兑换时自动登录，但同样可能顶号。
- 旧版本曾在项目上一级留下 `certificates/`，升级后可手动删除一次。
- 抖音单独采集可运行 `npm run capture:douyin`。

### 采集异常恢复

控制台启动时检查上次采集留下的恢复记录，并在账号页提示待恢复状态。可在账号页点击恢复，或运行 `.\start-console.cmd recover`、`node tools/start-console.mjs recover`，按记录还原本次代理改动并移除本次安装的证书。恢复结果会重新校验，失败时保留记录供后续重试。

采集恢复记录默认位于 `data/capture-session.json`，遵守 `CW_DATA_DIR`，也可用 `CW_CAPTURE_STATE` 指定文件。

### 手机号登录

控制台 **账号 → APP 账号登录** 适用于益世界 APP 账号。先在游戏 APP 确认账号和角色所属区服，微信、抖音小游戏角色使用对应的电脑客户端添加入口。APP 和小游戏角色可能属于不同渠道。

1. 选择账号密码或短信验证码登录。APP 登录统一使用已验证的益世界配置，自动完成业务和账号 SDK 初始化。首次登录或获取验证码时，工具会自动生成设备档案并保存到 `data/ewan-device.json`，后续持续复用。**首次使用** 区域显示当前状态，**高级选项 · 导入设备档案** 中可查看实际保存路径或导入已有 APP 档案。
2. 使用 **账号密码** 时，填写 APP 账号或绑定手机号及 APP 登录密码，点击 **登录并读取角色**。忘记密码可在 APP 中找回，或切换到 **短信验证码**。
3. 使用 **短信验证码** 时，填写 APP 绑定的 11 位大陆手机号，点击 **获取验证码** 并确认发送，收到后填写验证码，再点击 **验证并读取角色**。同一手机号发送成功后需等待 60 秒才能重发。
4. 列表显示各角色的游戏昵称、区服、等级、战力和所属 APP 账号。短信关联多个 APP 账号时会逐个查询并展示全部已有角色，合服角色同时显示原区服与当前区服。点击要使用的角色后，选择 **保存所选角色**。部分账号读取失败时可单独重试，认证失败时需返回重新登录。
5. 页面顶部的当前账号会切换到所选账号，后续 **连接** 使用所选区服。同一个 APP 账号保存为一条本地记录，再次选择其他区服会更新该记录的角色。切换已有在线账号的区服时，会停止旧角色的任务和连接，再由用户连接所选角色并启动任务。

读取角色列表需要登录游戏，可能让当前游戏客户端下线。已在线的控制台账号会复用现有连接读取列表。首次进入的 APP 账号按游戏服务端规则分配角色，查询结果为空时需要先核对游戏渠道或到 APP 中确认角色。

密码和验证码仅用于本次验证，待保存凭证在内存中保留 10 分钟。到期后页面提示重新登录。本轮修复已处理新设备缺少 SDK 初始化导致的 1068。若仍有认证错误，应核对 APP 中使用的账号信息。初始化或认证超时后可重试。

已有 APP 设备档案可通过高级选项导入，用于兼容性排查。JSON 需包含 64 位十六进制 `di` 和 16 位十六进制 `deviceCode`，显式 `oi` 的十六进制长度需为 32 的正整数倍，省略时按登录密钥加密空 OAID。导入档案使用原有显式字段。档案读取或格式校验失败时，页面会显示错误并展开导入入口。

CLI 等价入口：

```powershell
$env:CW_PHONE='手机号或账号'
$env:CW_PHONE_PASSWORD='登录密码'
node src/app.mjs accounts login-phone --probe   # 只看登录响应字段
node src/app.mjs accounts login-phone           # 预览游戏 openId，不保存
node src/app.mjs accounts login-phone --save --yes

# 已拿到短信验证码时（控制台可点击“获取验证码”）
$env:CW_PHONE='153xxxxxxxx'
$env:CW_PHONE_CODE='123456'
node src/app.mjs accounts login-phone --code "$env:CW_PHONE_CODE" --probe
```

早期协议采集记录见 [手机号登录分析](phone-login.md)。

## 海面生产状态

**建筑一览 → 海面**按工厂、农田、空位的顺序展示，活动工坊列在工厂表格中。工厂表格显示建筑、类型、等级、当前产物、自动生产开启状态和下一产物，当前产物附制造倒计时。点击“查看排产”可打开独立弹窗，查看全部生产格的产物、等待生产和空闲状态。弹窗支持“关闭”按钮和 Esc 键，海面刷新时同步更新详情。农田表格展示地块、等级、当前作物及成熟倒计时。

倒计时按服务器时间每秒更新。队列中尚未提供结束时间的项目显示“等待生产”，缺少成熟时间的作物显示“成熟时间未同步”。点击“刷新数据”可重新读取排产与收获状态。

## 需求联合排产

连接账号后，在 **建筑一览 → 需求联合排产** 点击 **计算联合排产**。每次计算重新读取当前订单、已开启来源的消费备料、完整库存、建筑与生产队列。计算复用 **游戏配置 → 工厂 → 需求优先级** 的保存顺序，先最小化最高级需求的齐套时间，再依次优化后续级别。同级需求共同优化工期，结果展示分层齐套时间、逐批投料和缺料、未解锁、读取失败的原因。

共享原料统一分配，已排队任务的成本视为已支付。高优先级需求沿产品配方传递到所缺的中间材料与种子，需求获得库存或在途覆盖后重新计算继承级别。共用生产位与原料的任务遵守占用约束，独立生产位可以同时开工。高优先级任务等料时，共用设备可插入能够在其开工前完成的低级任务。整体方案以高级齐套时间优先，随后比较低级齐套时间。

建筑备料同时遵守来源选择、**缺料时为建筑备料** 开关、首建或升级开关、前置建筑、等级人口与禁用设置。已齐的建筑材料在方案中独占保留。常规备货水位按库存策略处理。当前订单中未列入优先级列表的来源在最后一级计算。用户开启的博物馆、海兽等消费备料使用相应来源的级别，材料备齐后独占保留。

工厂排队格数与并行生产位分别计算，农田按单批产量合并需求，自定义种植遵守作物清单和开工水位。已有任务继续执行，新增任务遵守当前生产开关、配方等级、仓容、活动窗口和订单截止时间。本人已占用的联盟商船船舱已有提交材料证据。

计算采用固定快照、当前设施等级和确定的在产收益。齐套后的已启用订单按立即提交释放库存估算，关闭提交的订单独占相应材料。生产、收获与提交采用零操作延迟，其他消费与备货任务需让出相应原料和产能。外部采集、购买、广告和道具加速、未来升级收益需在新快照中确认后重新计算。

“按配置优先级的模型内最优”表示在页面列出的约束与耗时下，已经证明逐级最优。后续层的最优值以更高级需求已优先满足为条件。配置公式推算的耗时会标为估算，会话内观察到的同厂同产物耗时标为实测。搜索达到预算时展示当前可行方案和下界，缺失必要状态或原生自动生产持续追加任务时显示待确认。联盟招募的刷新时间作为重新核验边界，预计齐套越过该时刻时显示需求待确认。计算结果通过只读接口生成，可作为调整生产顺序的依据。

## 功能一览

页面按 **总览 / 挂机 / 游戏配置 / 建筑一览 / 挑战 / 资源与玩法 / 账号** 分组。挂机页提供自动功能的启停和配置入口，执行细项、策略、消费权限和参数通常在游戏配置修改。不差钱商人与超凡英雄的开关集中在资源与玩法的活动详情中。当前状态在总览查看。

### 基地与养成

| 功能 | 行为与配置 |
| --- | --- |
| 建筑与工厂 | 收成品、竣工、空位建造、升级及建材备料；可禁用建筑或工厂、保留蓝图、限制每轮建造与升级次数。库存、队列中和待收产品共同计入备料，同等需求优先级先排耗时短的产品；按实际空余制造位连续下单，整批核对结果，升级缺料同样一次安排所需多件 |
| 工厂需求 | 调整通用需求来源顺序，移除来源即停止为其安排；联盟募兵和红船的独立备料开关不依赖此顺序，但仍需开启工厂生产。支持指定来源加速、库存水位和加速器保留。可协作调整已开启的游戏原生自动生产，保留已有队列，调整间隔至少 60 秒 |
| 农田与港口 | 自动选种与自定义作物互斥，自定义按所选顺序和库存水位种植，收割独立控制；港口可限制每日装货批次，收货不占额度 |
| 居民订单 | 角色 12 级起自动协商含「不准消耗」材料的订单。该槽位等服务器换单，其余订单照常处理。低奖励等条件由原自动换单开关控制，达到每日上限时停止自动交单和协商。建筑一览支持逐张手动提交 |
| 采集与钓鱼 | 挂机页只显示“采集”总开关；在游戏配置 → 采集选择钓鱼、潜水、拾荒、原料漂浮物、藏品宝箱和工具养成，关闭总开关保留所有细项。自动采集要求对应玩法达到 2 级。潜水、拾荒开启后按挂机间隔每轮搜索一次，优先补缺，满仓、溢出或空奖励均继续；升级成功当轮使用新等级额度，达到养成目标不停止搜索。钓鱼满仓时跳过，可设继续处理图鉴；潜水后使用已有钥匙，每轮最多一把，开箱也受采集总开关控制 |
| 随机事件 | 为已支持事件设置默认选项；海上资源补给固定选择建造居民房，居民离开固定选择让其离开 |
| 邮件领取 | 检查全部邮箱分页，处理未读邮件和未领附件；领取后按邮件 ID 回读确认，状态未确认时不报成功 |
| 英雄与阵容 | 手动升级、升星、升技能、任命、补装备空槽及单件强化；自动养成可选英雄、目标等级/星级、经验保留和万能碎片权限。推荐阵容取自游戏内攻略，点击才换阵，出征中的舰队不能换阵 |
| 藏品养成 | 自动激活藏品、升星、提升藏品大师等级和套装等级。可限定激活/升星/套装品质、目标星级、目标大师等级、金币保留和每日套装金币预算；升星可用万能碎片补足，激活只使用普通碎片。只消耗现有碎片、经验与金币，不购买、不使用钻石，结果未知时保留记录 |
| 海兽培育 | 23 级建成培育室后，可按所选品种和品质上限领取、培育、投喂、进阶，单独控制万能基因与放生 |
| 博物馆 | 挂机页统一为“博物馆探宝”总开关，自动探宝、旧规则探险/领奖和升级在同一配置页选择，暂停不清空细项。28 级建成后按地图与英雄条件派队，支持 1–3 倍时长、按材料匹配倍数和指南每日上限；到期先结算再领奖，确认后继续派队 |

商人订单、贸易港和居民订单的材料会参与预留。商人订单未齐时可以交付已备齐的居民单，再安排补产；商人订单齐备后按其提交开关处理。联盟订单默认关闭，每轮最多一单，只使用扣除其他订单预留后的现有材料；需要补产时另开“联盟 · 募兵与互助 → 募兵缺料自动备料”，达到游戏或用户每日上限后停止为下一单备料。新旧海面、港口、基地和锻造流程共用材料与金币扣款检查，手动居民交单同样受保护：先核实订单、养成进度或队列等业务结果，再读取完整库存结算，补产或金币收入不再因余额高于历史扣款阈值而卡住。未知操作保留相关材料，其他材料可继续使用；同一进程内重新连接会继续核对，不按超时直接清空记录。装备锻造若产物由游戏内其他入口处理，装备锻造预览会显示“确认已处理并解除”，只允许在工厂空闲且用户明确确认后清理旧记录，不退回已确认消耗。

**工厂开关的区别：** “按需求调整游戏自动生产目标”只控制游戏内已开启的原生自动目标；普通排产由“自动生产”和“按需优先生产”控制。关闭“按需优先生产”后，普通排产按备货水位从短到长补库存；联盟募兵、红船的独立备料开关仍各自生效。协议每条请求只能安排一件，工具会按本次空位串行安排一批（当前游戏配置最多 6 格），不会超过空位或跳过库存核对反复下单。批次遇到拒绝、暂停或断线时停止后续下单，可能已发送的部分继续保留核对记录。

**工厂自动接续：** 挂机期间优先按服务器返回的最早完工时间安排收取与补产，建筑状态推送可提前唤醒，不必等到下一主挂机轮。尚未开工的排队项可能没有完成时间，不会按配方耗时猜测剩余时间。“游戏配置 → 工厂 → 兜底检查间隔”可设 1–300 秒，默认 30 秒，用于没有可靠时间、缺料、满仓或检查失败时复查；已知时间仍优先处理。完成与状态变化检查合并处理，最短间隔 1 秒，防止忙轮询。主轮在业务完成后的安全位置检查工厂，所有请求仍按账号串行；当前业务或网络请求尚未完成时会顺延，不保证零延迟。停止挂机、断线或达到有限轮数后，接续检查一同停止；命令行循环同样支持接续。

农田播种发送前复查空地，等待业务回包后再核对地块作物与完整库存，避免补货掩盖种子扣减而一直等待。结果未知时只保留相关种子和地块，不阻止其他材料的操作；后续读取继续确认，不因超时或重连直接重复播种。日志会区分“已确认”和“等待确认”。

博物馆探宝发送前复查地图、英雄占用和材料需求，派遣后先核对服务器队伍或已领取的关卡进度，再读取完整库存。工厂补产使库存持平或增加时，也能确认旧扣款并恢复贸易港装货；丢回包或重连后会继续核对。尚未确认的探宝仅保留相关材料、地图与英雄，不阻止贸易港使用其他材料，单凭超时或库存下降不会重复派遣。

详细锻造在领取确认后续产，达到下单上限仍可领取。工具按服务器当前批次接续游戏内加速、领取和换配方后的任务，已确认开工的消耗继续计入预算。游戏内原生自动锻造开启期间等待，关闭后继续检查。暂停托管或顶号后重新登录时，会同步装备厂、装备、材料和金币。旧未知请求归档并保留预算，当前工厂按新状态安排。同步读取失败时等待后续连接重试，普通网络重连继续核对原请求。

装备分解与海兽放生会随对应模块每轮扫描库存，只处理所选品质中闲置、未养成的对象。蓝紫橙海兽的天然高星可参与放生，已升星的红色海兽会保留。玩家手动处理后，托管恢复时会重新读取库存与占用，核销已消失的 UID，并在复核通过后继续处理在场对象。工具无法读取游戏客户端保存在本地的锁定标记。

**城战攻守目标**

进入 **游戏配置 → 联盟/城战**，选择参与舰队并逐队设置职责。进攻和防守分别配置目标来源、城市名单和优先策略。以一队攻 A 城、二队守 B 城为例。

1. 将一队设为进攻、二队设为防守。
2. 将“进攻目标来源”设为“只选择指定城市”，在“指定进攻城市”中选择 A 城。
3. 将“防守目标来源”设为“只选择指定城市”，在“指定防守城市”中选择 B 城。
4. 如需立即由工具按此配置接管，将原生委任次数设为 **0**。保存完成后，可先选择“联盟/城战”只读预览，核对两队目标。

两侧也可分别使用自动和指定模式，例如进攻跟随联盟有效目标、防守固定 B 城。每侧在自己允许的目标范围内按队数与距离，或按集结／指定城市顺序选城。进攻目标须为本盟已宣战的敌城，防守目标须为正在受宣战且仍属本盟的城市。该侧没有有效目标时等待。

升级时保留已设置的舰队职责。缺少独立防守目标字段的旧配置会把原共享目标设置复制到防守侧，之后两侧可分别修改。配置导入采用相同迁移规则。

城战的攻守分工和目标配置在工具接管后生效，原生委任跟随联盟集结。工具使用舰队已保存的英雄编队，在服务器城战时段处理有效攻防目标，并跳过舰队当前所在城市。发送前重新核对宣战、归属、职责和该侧目标配置，城市失守或宣战结束就取消旧计划。最后一次读取与服务端实际处理之间仍可能发生城市归属变化。

城战的工具派遣日上限不包含原生委任，免费防守仍计入次数；原生委任次数设为 0 或 N 且达到接管条件时，工具会关闭所选舰队的原生委任开关，确认关闭后才按工具预算出战。防守队列直接使用服务器计数，不保证排除城防 NPC；正在交战的舰队只统计对应一侧的本盟非 NPC。维修与付费行军共用城战日汽油预算，免费驻防不因汽油预算耗尽或库存低于保留量而阻止，但仍检查耐久、派遣次数与舰队占用。战后维修使用普通维修，不花钻石或加速器。舰队任务结果未知时保留记录并核对服务端状态；不能仅凭舰队空闲就把未知任务记成成功。

**自动推关设置：** 在 **挂机 → 世界 → 推关与试炼 → 配置** 中开启主线/闯关或试炼，选择副本，自动保存完成后开始挂机；海盗讨伐在同组的独立入口设置舰队与预算。主线、每个试炼分别记录同一关的连续战败，海盗记录连续战败；成功通关或首杀后对应计数清零。**失败停止次数**默认 3，可设 1–100，不是挑战总次数。达到上限后本次挂机不再挑战对应玩法，其他任务继续；跨轮次与断线重连保留计数及海盗汽油预算，暂停后重新开始挂机会重置本次计数。未确认的海盗派遣仍由持久记录拦截，不会因重启而重发。

**手动挑战：** 在 **挑战** 页手动开始/停止主线、试炼和海盗首杀推进；试炼保留“挑战一次”。本页失败停止次数独立于挂机配置，主线/试炼默认 3 次，海盗手动推进默认 1 次；操作不会开启挂机。主线与试炼共用至少 5 秒的挑战发送间隔，避免同轮切换玩法触发服务器限频。服务器明确拒绝不算战败，自动任务下轮再检查；战报超时或结果不明仍停止重发。

**已开启的广告任务默认也为无免广告权益账号领取。** 不再单独提供无权益开关，旧配置中的关闭值也不再阻止领取。工具提交广告申请，不播放视频，等待设定秒数后直接领奖；有权益时立即领取。这不是游戏客户端的正常流程，服务器可能识别，存在账号处罚风险，需自行评估。等待秒数默认 15，可设 5–120。现有测试记录中，15 秒在 7 个入口成功；5 秒只在藏品招募成功；广告商店 3 秒被拒。试炼扫荡、建筑加速和博物馆加速尚无真实账号验证记录。

无权益模式下，等待期间账号操作队列会被占用，所以整轮挂机每轮最多处理 1 次（挂机收益除外），手动试炼扫荡和手动走江助力不受此限。等待中暂停或断线时不发送领奖；服务器返回“广告未完成”时跳过该入口并冷却 5 分钟；结果未知时保留记录，核对次数后才继续，不重复提交。

### 总览、地图与工具

- **运行概览**：按功能分组显示当前进度和条件，可搜索、筛选异常/受限项。分组展开时保持单列顺序，不改变其他分组位置。角色区服显示游戏内名称（如“海岛1986服”）和 worldId，账号列表与区服列表同样显示名称。
- **世界地图**：只读显示城市、货轮和舰队，支持拖动、Ctrl+滚轮缩放、图层过滤、定位舰队与选中详情，并展示城战、货轮和汽油统计。自动刷新可设 5–300 秒，默认 10 秒，独立于挂机间隔；行军位置按已同步的起终点和时间推算。
- **礼包兑换**：勾选一个或多个账号（默认当前账号，已暂停账号不可选），每批 1–100 个不同礼包码，按换行、逗号、空白或分号拆分去重，各账号分别保存记录并显示进度。兑换页可从内置初始码目录载入待尝试的首批/后续批次；目录来源于[疯狂水世界 Wiki 兑换码页](https://numb9870.github.io/crazy-water-world/%E5%85%91%E6%8D%A2%E7%A0%81/)，并保留收录日期与页面标注的有效期。账号各自排队，兑换请求跨账号逐个发送。成功、已用或结果未知的码不对该账号重发；连接失败或结果未知只停止该账号的余码，服务器限频时同批尚未发送的账号一起停止。
- **掉线处理**：心跳独立于业务操作，每次允许 10 秒应答，连续 3 次无应答才断线。挂机中的心跳超时、普通网络中断或消息重传失败会按 3、6、12、24、48、60 秒（上限 60 秒）退避重连，成功后继续原进度；有限轮数只计算完整轮次。旧轮次退出后才恢复，不清除未知操作的预算或材料预留。网页会显示网络恢复状态，CMD 记录重连次数和结果。
- **异地登录恢复**的自动重连默认关闭。在 **登录设置** 开启后，被顶号的账号会按已配置的常规间隔、深夜时间段与间隔、随机抖动和重试上限自动恢复连接，并先同步当前工厂、农田与库存。原有挂机继续运行，未运行挂机的账号恢复连接后保持挂机停止状态。等待时间和已尝试次数按账号持久保存，重启控制台后接续等待。等待期间保存登录设置会立即重算下一次重试时间，网页刷新和只读查询遵守这次等待。手动暂停托管、停止挂机或断开连接会取消自动重试，关闭自动重连开关、凭证失效、协议错误或耗尽重试次数也会结束重试。手动暂停托管后仍需自行恢复托管。
- **日志与手动入口**的中文业务日志同时输出到网页与 CMD，关闭网页后仍输出轮次、动作和停止原因。网页可按功能或警告/错误筛选，重新打开会回放最近记录。建筑一览提供一轮海面经营及逐张居民单操作。英雄装备/阵容、联盟及活动单次操作也继续可用。同一账号与挂机串行执行，发送前复查条件。原始协议日志 `data/protocol.log` 按 5 MB 轮转到 `data/protocol.log.1`，可用 `CW_PROTOCOL_LOG_MAX_BYTES` 调整上限。`CW_DEBUG=1` 才额外向终端输出原始协议。

顶部固定区仅用于支持 VT 的交互终端；重定向到文件、不支持的终端或过小窗口自动使用普通文本。设置 `CW_PIN_HEADER=0` 可关闭固定区。终端输出分批处理，积压超过缓冲上限时会提示省略较早记录，网页日志仍按原规则保留。Windows 旧控制台选中文字可能暂停程序；长时间挂机时避免保持文本选择状态。电脑休眠期间无法发送心跳，唤醒后的普通网络断线会进入上述恢复流程。

### 问题反馈日志

工厂、农田、海兽或其他功能开启后没有动作时，先看日志中的结果：**“已跳过”“等待确认”“材料扣款尚未确认”都不表示执行成功**，“信息”只是日志等级。材料扣款待确认表示之前的操作尚缺完整核对证据。自己进入游戏后继续生产、领取成品或改种，会改变工厂队列、待收成品和地块，可能使旧操作无法再由这些状态确认；回包或库存同步失败也可能造成等待，不能仅凭这一行日志认定具体原因。

主动暂停后的操作流程为 **暂停托管 → 进入游戏操作 → 退出游戏 → 恢复托管**，随后按原流程开始挂机。希望异常顶号后自动接管时，请在登录设置中开启自动重连，工具会按已配置的时间等待恢复。工具接管时会自动读取完整工厂、农田和库存，归档已无法核对的旧普通排产、播种占用，并按当前状态重新规划，不需要额外同步按钮或确认操作。已开启的顶号自动重连，以及原有“连接”“恢复托管”“开始挂机”入口，都先完成这次同步。旧操作保留为未知，不记成功；预算以及海兽、钻石或其他玩法的待确认记录保持原状。读取失败时保留旧记录并暂缓写入。自动重连和运行中的挂机会按相应重连策略重试同步，其他情况下由后续页面读取或正常开始挂机重试。同步期间界面显示“正在同步生产状态”。

遇到异常请先保留日志，不要先删除 `data/` 或重装。更新并重启后若仍能复现，请在复现后及时复制日志，避免后续轮转覆盖；在运行日志窗口点击 **问题反馈（附日志）**，或使用 [问题反馈表单](https://github.com/xutongxue233/crazywaterworld/issues/new?template=bug_report.yml)。已有对应 issue 时直接补充到原帖，附上：

- `protocol.log` 和 `protocol.log.1`（存在时），可压缩成 ZIP 上传。默认位于项目 `data/`；设置了 `CW_DATA_DIR` 时到该目录查找。请提供问题发生前后的一段完整日志，截图可作为补充。
- 发生的北京时间、复现步骤、预期行为和游戏内实际结果；说明是否在手机/电脑游戏客户端登录同一账号，是否先暂停托管，手动进行了生产、收成品或改种，以及自动重连或恢复托管后的同步结果。
- 当前版本（可运行 `git rev-parse --short HEAD`）、启动方式、Node.js 版本（`node -v`）以及相关挂机开关和详细配置截图。工厂/农田写明建筑和产品，海兽写明驻扎建筑和目标，舰队问题写明编号。

协议日志中的登录凭据在写入前脱敏。**只上传上述日志和必要截图，不要上传整个 `data/`、`accounts.json`、账号导出文件或登录凭据。** 若无法取得日志，请说明原因；这些信息用于区分配置条件、未知操作保护、顶号和程序错误。

## 配置与预算

游戏配置修改后自动保存，无须点击保存按钮：停止输入约 0.6 秒后合并提交，保存期间继续修改会排队保存最新内容，导入通过校验后也会自动保存。保存进度仅更新顶部常驻状态文字，不再反复展开成功提示条；状态文字保持单行，避免保存时页面跳动。输入不完整或校验失败时保留更改，修正后自动重试。网络失败最多自动重试 3 次，持续失败时提供重试入口；多页面版本冲突不会强制覆盖，需重新载入后修改。开始任务或切换账号前会等待保存完成，关闭网页时仍有未完成保存会提示。保存只更新当前账号，不启动挂机。只读预览按当前配置读取真实游戏状态并计算计划，不发送资源操作，运行安排预览无需连接。执行前仍会复查，预览结果可能随游戏状态变化。

联盟与硅矿入口位于 **游戏配置 → 世界 → 联盟 · 募兵与互助／联盟 · 商船／联盟 · 工事捐赠／硅矿**。这些模块的总开关在挂机页，配置页可直接跳转。联盟商船和工事同时需要打开 **挂机 → 世界 → 联盟募兵与互助**。不差钱商人、海商王与超凡英雄的配置统一在 **资源与玩法 → 活动** 各自详情中自动保存。三个硅矿舰队的独立参数、时间和名单都沿用账号自动保存。新增消费总开关默认关闭。各模块的配置与协议说明见项目文档。[项目文档](#项目文档)

挂机页的开关点击后立即保存；轮数与间隔在点击“开始挂机”时保存，已有详细配置时同步写入同一份账号配置，刷新或重启后继续保留。修改挂机开关或开始挂机前会先自动保存待提交的详细配置，校验失败或版本冲突时会提示处理。有限轮数只记住参数，不会在重启后自动续跑；只有持续挂机会自动恢复。

已结束的限时活动会从游戏配置、挂机任务列表和运行安排中隐藏，并停止相应自动任务；原开关、参数、导入导出字段和实现代码均保留。服务器再次下发当前开放的对应子活动时，后台按原设置恢复，重新载入配置即可看到对应入口，其他尚未开放的子活动继续隐藏。刷新活动状态不会覆盖未保存的配置草稿。

截至 2026-11-12，已下线截至 11-11 的酆都诡事联动配置，包括走江踏浪、酆都法旨、驱邪除祟、龙王罗盘及联动签到/礼包。海上风采大赛的公告投票期包含 11-12，暂时保留；满减商店延至 11-13，本工具未设置其自动消费入口。周活动、海商王、军备竞赛及按账号或区服开放的活动不受影响。官方时间依据和恢复规则见 [活动配置下线记录](activity-availability.md)。

原有的联盟订单、联盟情报、装备制造、博物馆和海兽细项独立保存。博物馆探宝与联盟情报在挂机页各合并为一个总开关，在游戏配置中选择原规则或详细策略；关闭总开关同时暂停两条路径，重新开启不会丢失选择。为兼容旧账号，这两个总开关缺省为开启，但不会额外开启任何消费细项；未选择动作时会提示先配置。对应详细模块生效时接管同一功能，防止新旧路径重复执行。缺省字段升级时补齐，已有显式开关值不重置。基地总开关只管理基地动作；英雄自动养成由挂机页的一个开关统一启停，配置中只选择养成动作、目标与资源保留。

硅矿追杀在 **游戏配置 → 世界 → 硅矿 → 对应舰队** 开启，每行填写一个完整昵称。指定名单优先于空位，只攻击名单内且符合限制的玩家，没有合规目标时可占空位；安全名单、同盟保护、只占空位、矿级、战力及预算限制仍优先。首次产矿前游戏不允许撤退，选择“发现名单目标先撤再打”也需先等首奖；撤回并确认回港后重新核对目标，返航期间不会强行出征。追杀按两分钟检查并响应相关推送，不限于原有三日周期的黑名单追击窗口；矿位协议没有玩家 ID，同昵称无法进一步区分。

**钻石总开关默认关闭**，每日总预算默认 `2000`，钻石保留阈值默认 `0`；日预算为 `0` 时禁止自动花钻石。总开关不会替你开启点金、付费扫荡或购买等项目。各项目限制与总预算同时生效，建筑、工厂等使用加速器时共用保留数量。

配置在 `data/automation-settings.json`，持久用量与防重记录在 `data/automation-usage.json`，按账号保存、北京时间零点换日。发送前先占用预算；明确未发送或拒绝才释放，已发送但结果未知的操作保留占用，带防重键的未知任务跨日继续等待确认。保存配置或重启不会清除这些记录。本工具用量不等于游戏内全部消费，升级前和在游戏里直接进行的消费不计入工具总账。

材料、金币和舰队预留与持久账本配合，避免多个玩法重复使用旧余额。业务确认后仍须取得随后完整的库存或资源快照；读取失败、数据不完整、切号或结果未知时继续保护。联盟互赠及商人订单补料在已收到明确回执后，可于后续读取恢复确认；完全丢失回执且没有可归属本次操作的证据时，仍保留防重记录。配置导出只含玩法设置，不含登录凭据或用量账本；账号导出是含凭据的另一项功能。

战报奖励的新旧开关共用同一领取流程与持久防重记录，挂机时任一开关开启即可检查，同时开启也只执行一次。手动活动、单次领奖、挂机和推送共用该记录，任一入口领取结果未知时，后续检查继续等待确认，不会通过另一入口重发。

## 数据与安全

- `data/`：账号、设置、用量账本和本地日志，含登录凭据，不要提交或外发。
- `work/`：游戏协议、配置和素材缓存，不随仓库分发。
- `certificates/`：抓包 CA、目标证书和代理备份，路径按项目位置计算，不依赖盘符；可用 `CW_CA_DIR` 指向其他目录。抓包结束并移除证书后自动清理，选择保留 CA 时保留。
- `src/ui/dist/`：控制台页面构建产物，随源码提交。
- 控制台只监听本机回环地址，没有登录校验；不要把端口直接暴露到公网。
- 账号导出和礼包兑换记录可能包含凭据或账号信息，请留在本机。

## 开发与辅助命令

| 命令 | 用途 |
| --- | --- |
| `npm run build:ui` | 修改 TSX、页面脚本或主题样式后生成页面与样式 |
| `npm test` | 构建界面并运行全部回归，包含真实协议编解码验证 |
| `npm run test:offline` | 使用显式测试数据运行核心回归，无需本机游戏协议包 |
| `npm run typecheck` | 检查持久化与用量账本的类型约束 |
| `npm run test:core` | 核心协议、日常、原有玩法、阵容和掉线处理回归 |
| `npm run test:progression` | 装备、情报、联盟订单、博物馆、海兽、藏品、资源预留和迁移接线回归 |
| `npm run test:extra` | 详细配置、活动、调度、战后维修、城战/锻造、礼包与地图等额外回归 |
| `npm run test:capture` | 原始抓包、代理、锁和抖音 CLI 回归 |
| `npm run test:wechat` | 微信抓包与登录 CLI 回归 |
| `npm run test:wxapkg` | 微信小游戏包解密与解包回归 |
| `npm run sync-config` | 从本机微信缓存同步配置表到 `work/` |
| `npm run sync-art` | 同步游戏素材；缺图时可加 `-- --fetch` 从 CDN 补齐 |
| `npm run capture:douyin` | 单独采集电脑版抖音登录样本 |
| `node src/app.mjs actions` | 查看协议操作目录 |
| `node src/app.mjs probe` | 连接并读取探测信息 |

`npm test` 需要本机可读取游戏协议包；没有协议缓存时，先在电脑版微信打开一次游戏，或设置 `CW_PROTO_BUNDLE` 指向自己的 `_src_chunks_.wxapkg` 或解包后的 `game.js`。
